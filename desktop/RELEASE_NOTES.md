# gpx2elev 0.5.1 : tuiles partagées entre processus / Tiles shared across processes

- Une tuile Mapterhorn lue sur le disque n'y est plus réécrite. Plusieurs processus qui calculent en même temps dans la même région, comme les quatre que lance gpx2dash, se gênaient sous Windows : remplacer un fichier qu'un autre processus lit y échoue, et cet échec faisait retenir pour toute la trace un modèle moins bien classé (FABDEM au lieu de Mapterhorn), ensuite conservé en cache.
- Une tuile téléchargée qui ne peut pas être enregistrée (disque plein, fichier occupé) sert quand même au calcul en cours. Un raster FABDEM ou Copernicus publié au même instant par un autre processus est réutilisé.
- Les requêtes annoncent la vraie version de gpx2elev, sur ordinateur comme sur Android ; elles se présentaient encore comme les versions 0.2.2 et 0.1.
- Protocole de calcul inchangé : les dénivelés restent identiques.

A Mapterhorn tile read from disk is no longer written back. Several processes computing at the same time in the same region, such as the four that gpx2dash starts, got in each other's way on Windows: replacing a file that another process is reading fails there, and that failure made the whole track fall back to a lower-ranked model (FABDEM instead of Mapterhorn), which then stayed in the cache. A downloaded tile that cannot be saved (full disk, busy file) is still used for the current calculation, and a FABDEM or Copernicus raster published at the same moment by another process is reused. Requests now report the actual gpx2elev version on desktop and Android, instead of 0.2.2 and 0.1. The calculation protocol is unchanged, so elevation gains stay identical.
